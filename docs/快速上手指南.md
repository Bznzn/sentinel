# Sentinel 快速上手指南

本指南帮助你从零开始使用 Sentinel 安全事件智能研判平台。

## 前置条件

确保以下服务已启动：

- ✅ Milvus 向量数据库（`manifest/docker/docker-compose up -d`）
- ✅ MySQL 数据库（`docker-compose up -d mysql`）
- ✅ 后端服务（`go run main.go`，监听 6872 端口）
- ✅ 前端服务（`cd web && npm run dev`，默认 3001 端口）
- ✅ 配置文件中已填写有效的 Ark API Key

---

## 第一步：创建数据订阅源

### 为什么需要订阅？

Sentinel 需要从外部数据源采集安全事件，订阅是数据的入口。

### 操作步骤

1. 访问订阅管理页面：
   ```
   http://localhost:3001/subscriptions
   ```

2. 点击 **"新建订阅"** 按钮

3. 填写订阅配置：

   **基础配置示例：**
   ```
   订阅名称：NVD 漏洞监控
   数据源类型：nvd
   源地址：https://nvd.nist.gov/feeds/json/cve/1.1/nvdcve-1.1-recent.json
   ```

   **高级配置（可选）：**
   ```
   定时抓取：0 */6 * * *  （每6小时执行一次）
   关键词过滤：Apache,Windows,Linux,MySQL
   最低严重程度：high
   抓取超时：60秒
   ```

4. 保存订阅，状态设为 **active**

5. 点击订阅卡片上的 **"手动抓取"** 按钮，立即触发一次数据采集

### 推荐的数据源

| 数据源类型 | 示例地址 | 说明 |
|-----------|---------|------|
| NVD | https://nvd.nist.gov/feeds/json/cve/1.1/nvdcve-1.1-recent.json | 美国国家漏洞数据库 |
| RSS | https://www.cvedetails.com/vulnerability-feed.php | CVE 详情 RSS 订阅 |
| GitHub | https://github.com/advisories | GitHub 安全公告 |

### 验证采集结果

- 查看订阅卡片上的 **"累计抓取事件数"**
- 访问 **抓取日志页面** 查看详细日志：
  ```
  http://localhost:3001/logs
  ```

## 第二步：查看原始事件

### 操作步骤

1. 访问事件列表页面：
   ```
   http://localhost:3001/events
   ```

2. 此时应该能看到一些事件，状态为 **new**（未经 AI 处理）

3. 这些原始事件包含：
   - 标题
   - 描述
   - 来源链接
   - 采集时间

4. **注意**：原始事件还没有以下信息（需要 AI 分析后才有）：
   - ❌ CVE 编号
   - ❌ 风险评分
   - ❌ 受影响厂商/产品
   - ❌ 处置建议

## 第三步：运行 AI 多 Agent 分析管道

### 什么是多 Agent 管道？

Sentinel 使用 5 个 AI Agent 串联处理安全事件：

```
数据采集 → 智能提取 → 去重过滤 → 风险评估 → 解决方案生成
```

### 操作步骤

1. 访问事件分析页面：
   ```
   http://localhost:3001/events/analysis
   ```

2. 点击 **"开始分析"** 按钮

3. 观察 5 个 Agent 的实时处理过程（SSE 流式输出）：

   **Agent 1 - 数据采集**
   ```
   扫描数据库中 status='new' 的事件
   最多处理 10 条事件
   输出：采集到 X 条新事件
   ```

   **Agent 2 - 智能提取**
   ```
   使用 DeepSeek V3 提取结构化信息
   提取内容：标题、CVE 编号、严重程度、厂商、产品
   输出：成功提取 X 条事件
   ```

   **Agent 3 - 去重过滤**
   ```
   基于 MD5 哈希去重
   过滤重复和相似事件
   输出：去重后剩余 X 条事件
   ```

   **Agent 4 - 风险评估**
   ```
   AI 评分（0-100 分）
   评估严重程度和影响范围
   输出：风险因素和建议
   ```

   **Agent 5 - 解决方案生成**
   ```
   ReAct 推理循环（最多 25 步）
   调用 6 个工具获取信息：
   - query_events（查询历史事件）
   - search_similar_events（向量相似搜索）
   - query_internal_docs（RAG 知识库检索）
   - get_event_detail（事件详情）
   - query_prometheus_alerts（告警查询）
   - get_current_time（当前时间）
   输出：完整的处置方案
   ```

4. 等待处理完成（通常 1-3 分钟）

### 可视化功能

- **Agent 流程图**：展示 5 个 Agent 的执行顺序
- **实时日志**：显示每个 Agent 的思考过程
- **风险评分仪表盘**：可视化风险评分
- **推理链路图**：展示 ReAct 推理过程

## 第四步：查看 AI 分析结果

### 操作步骤

1. 回到事件列表页面：
   ```
   http://localhost:3001/events
   ```

2. 筛选条件设为 **status=processed**

3. 点击任意一个事件，查看详情弹窗

### AI 分析结果包含

| 字段 | 说明 | 示例 |
|------|------|------|
| CVE 编号 | 自动提取的漏洞编号 | CVE-2024-1234 |
| CVSS 评分 | 通用漏洞评分 | 9.8 |
| 风险评分 | AI 评估的风险分数（0-100） | 95 |
| 严重程度 | critical / high / medium / low / info | critical |
| 受影响厂商 | 提取的厂商名称 | Apache, Microsoft |
| 受影响产品 | 提取的产品名称 | Struts 2.x, Windows Server |
| 风险因素 | AI 分析的风险点 | ["远程可利用", "无需认证", "影响范围广"] |
| 处置建议 | AI 生成的解决方案 | 升级到最新版本，配置防火墙规则... |

### 事件状态管理

- 可以手动更新事件状态：
  - **new** - 新事件
  - **processing** - 处理中
  - **resolved** - 已解决
  - **ignored** - 已忽略

- 支持批量操作：勾选多个事件，批量更新状态

## 第五步：体验 AI 助手对话

### Supervisor 多 Agent 路由

Supervisor 会根据你的问题自动路由到最合适的专业 Agent：

```
用户问题 → Supervisor 路由 → 专业 Agent 处理 → 返回结果
```

### 操作步骤

1. 访问 AI 助手页面：
   ```
   http://localhost:3001/chat
   ```

2. 选择对话模式（4 种）：
   - **通用对话** - 标准聊天
   - **AI 运维** - 运维分析
   - **多 Agent** - Supervisor 路由（推荐）
   - **技能执行** - 预定义技能

3. 输入问题，观察 SSE 流式输出

### 推荐的测试问题

**事件查询类（路由到 Event Agent）：**
```
最近有多少个严重漏洞？
查询 Apache 相关的高危事件
今天新增了哪些安全事件？
列出所有 critical 级别的事件
```

**威胁分析类（路由到 Risk Agent）：**
```
分析 CVE-2024-XXXX 的影响范围
评估 Windows 漏洞的风险
这个漏洞有多严重？
```

**报告生成类（路由到 Report Agent）：**
```
生成本周安全事件周报
总结最近的严重漏洞
生成一份分析报告
```

**通用对话类（路由到 Chat Agent）：**
```
你好
解释一下 XSS 漏洞
什么是 SQL 注入？
```

### 观察 AI 思考过程

SSE 流式输出会展示：

1. **Supervisor 路由决策**
   ```json
   {"agent": "Event Agent", "reason": "用户询问事件统计"}
   ```

2. **工具调用**
   ```json
   {"tool": "query_events", "params": {"severity": "critical", "limit": 5}}
   ```

3. **Agent 思考**
   ```
   正在查询数据库...
   找到 15 个严重漏洞
   正在分析...
   ```

4. **最终回答**
   ```
   根据查询结果，最近 7 天共发现 15 个严重漏洞，
   其中 Apache 相关 3 个，Windows 相关 5 个...
   ```

## 第六步：上传知识库文档（可选）

### 为什么需要知识库？

知识库文档会被向量化存入 Milvus，Agent 可以通过 RAG 检索这些文档，生成更准确的处置建议。

### 操作步骤

1. 在 AI 助手页面，点击 **上传按钮**

2. 选择文档文件：
   - 支持格式：PDF, TXT, MD, CSV, DOC, DOCX
   - 文件大小上限：50MB

3. 上传后系统会自动：
   - 解析文档内容
   - 使用豆包 Embedding 生成 1024 维向量
   - 存入 Milvus 向量数据库

4. 后续 Agent 可以通过 `query_internal_docs` 工具检索这些文档

### 推荐的知识库文档

- 安全基线配置文档
- 应急响应手册
- CVE 分析报告
- 厂商安全公告
- 漏洞修复指南
- 安全加固方案

## 常见问题

### Q1: 订阅抓取失败怎么办？

**可能原因：**
- 数据源地址无法访问（需要 VPN）
- 数据源需要 API Key 认证
- 网络超时

**解决方案：**
- 检查抓取日志页面的错误信息
- 尝试使用其他数据源
- 增加抓取超时时间

### Q2: AI 分析管道卡住不动？

**可能原因：**
- Ark API Key 无效或额度不足
- DeepSeek API 调用超时
- Milvus 连接失败

**解决方案：**
- 检查后端日志：`resource/log/server.log`
- 验证 API Key 是否有效
- 检查 Milvus 容器状态：`docker ps | grep milvus`

### Q3: 向量检索结果不准确？

**可能原因：**
- 知识库文档太少
- 向量索引未建立
- 相似度阈值设置不合理

**解决方案：**
- 上传更多知识库文档
- 多处理几个事件，让 Milvus 建立索引
- 调整配置文件中的 `similarity_threshold`

### Q4: 前端无法连接后端？

**检查清单：**
- ✅ 后端服务是否启动（`curl http://localhost:6872/api/health`）
- ✅ 端口是否被占用（`netstat -ano | findstr 6872`）
- ✅ 防火墙是否拦截
- ✅ 前端 API 地址配置是否正确
