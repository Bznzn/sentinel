## 项目整体结构

Sentinel 项目采用标准的 Go 项目布局（Go Standard Project Layout），主要目录如下：

```
Sentinel/
├── api/                    # API 定义和协议文件
├── cmd/                    # 命令行工具和可执行程序入口
├── internal/               # 核心业务逻辑（私有包）
├── manifest/               # 部署配置文件
│   ├── config/            # 配置文件
│   └── docker/            # Docker 配置
├── web/                    # 前端项目（React + TypeScript）
├── utility/                # 通用工具函数（可被外部导入）
├── test/                   # 测试文件
├── docs/                   # 项目文档
├── main.go                 # 主程序入口
├── go.mod                  # Go 模块依赖
└── docker-compose.yml      # Docker Compose 配置
```

## 顶层目录说明

### api/
存放 API 接口定义和协议文件
- OpenAPI/Swagger 规范
- Protocol Buffers 定义（如果使用 gRPC）
- API 版本管理

### cmd/
命令行工具和可执行程序的入口点
- 每个子目录对应一个可执行程序
- 包含 main 函数
- 示例：数据迁移工具、管理命令等

### internal/
项目的核心业务逻辑（私有包）
- Go 的 internal 目录有特殊含义：只能被父目录及其子目录导入
- 包含所有业务逻辑、数据访问、AI 能力等
- 详细说明见下一节

### manifest/
部署和配置相关文件
- **config/** - 配置文件（YAML 格式）
  - config.yaml - 默认配置
  - config.local.yaml - 本地开发配置
- **docker/** - Docker 相关配置
  - docker-compose.yml - Milvus 集群配置
  - Dockerfile - 容器镜像构建

### web/
前端项目（独立的 React 应用）
- 技术栈：React 18 + TypeScript + Vite
- 样式：Tailwind CSS
- 状态管理：Zustand
- 详细结构见前端项目文档

### utility/
通用工具函数库（公共包）
- 可以被外部项目导入
- 包含与业务无关的通用工具
- 示例：字符串处理、时间格式化、加密解密等

### test/
测试文件和测试数据
- 单元测试
- 集成测试
- 测试数据和 Mock 数据

### docs/
项目文档
- 使用文档
- 开发文档
- API 文档
- 架构设计文档

## internal 核心包详解

internal 目录是项目的核心，包含所有业务逻辑。按功能分类如下：

### 1. AI 相关（核心功能）

#### internal/ai/
AI 能力的核心实现，这是 Sentinel 项目最核心的模块

```
internal/ai/
├── agent/          # Agent 实现
│   ├── collector/      # 数据采集 Agent
│   ├── extractor/      # 智能提取 Agent
│   ├── deduplicator/   # 去重过滤 Agent
│   ├── assessor/       # 风险评估 Agent
│   ├── solver/         # 解决方案 Agent
│   └── supervisor/     # Supervisor 路由 Agent
├── embedder/       # 文本向量化
│   └── doubao/         # 豆包 Embedding 模型封装
├── indexer/        # 向量索引管理
│   └── milvus/         # Milvus 向量数据库操作
├── retriever/      # RAG 检索器
│   └── rag/            # 检索增强生成实现
├── loader/         # 知识库文档加载器
│   ├── txt/            # 文本文件加载
│   ├── pdf/            # PDF 文件加载
│   └── markdown/       # Markdown 文件加载
├── models/         # LLM 模型封装
│   └── deepseek/       # DeepSeek V3 模型封装
├── tools/          # Agent 可调用的工具
│   ├── database/       # 数据库查询工具
│   ├── search/         # 搜索工具
│   ├── rag/            # RAG 检索工具
│   └── calculator/     # 计算工具
├── skills/         # Agent 技能定义
└── cmd/            # AI 相关的命令行工具
```

**作用说明：**
- **agent/** - 实现 5 个处理 Agent 和 Supervisor 路由逻辑
- **embedder/** - 将文本转换为 1024 维向量
- **indexer/** - 管理 Milvus 向量索引，支持相似度检索
- **retriever/** - 实现 RAG 检索，从知识库中检索相关信息
- **loader/** - 加载和解析知识库文档
- **models/** - 封装 DeepSeek V3 API 调用
- **tools/** - 提供 Agent 可调用的工具函数

数据库连接和初始化

- MySQL 连接池管理
- 数据库初始化和迁移
- 连接健康检查

#### internal/model/
数据模型定义（ORM 实体）

**主要模型：**
- Event - 安全事件
- Subscription - 订阅规则

- 对应数据库表的结构体定义
- GORM 标签和关联关系

#### internal/repository/
数据访问层（Repository Pattern）

**作用：**
- 封装数据库 CRUD 操作

- 提供数据访问抽象层

## 包的设计原则

### 1. 分层清晰
- **表现层**（Controller）：处理 HTTP 请求
- **业务层**（Service）：实现业务逻辑
- **数据层**（Repository）：数据访问
- **基础设施层**：数据库、缓存、消息队列等

### 2. 职责单一
每个包只负责一个明确的功能领域，避免职责混乱。

### 3. 依赖倒置
高层模块不依赖低层模块，都依赖抽象接口。

### 4. 可测试性
通过接口和依赖注入，便于单元测试和集成测试。

### 5. 可扩展性
- 插件系统支持功能扩展
- Agent 可以灵活添加和组合
- 数据源可以方便接入

## 关键技术点

### 1. AI 相关（internal/ai/）
这是项目的核心创新点：

**5 个 Agent 串联 Pipeline：**
- 数据采集 → 智能提取 → 去重过滤 → 风险评估 → 解决方案生成
- 使用 Cloudwego Eino 框架实现
- 支持 SSE 实时流式输出

**Supervisor 多 Agent 路由：**
- 根据用户问题智能路由到专业 Agent
- 支持事件查询、威胁分析、报告生成等场景

**RAG 技术：**
- Milvus 向量数据库存储事件向量
- 豆包 Embedding 生成 1024 维向量
- 相似度检索增强 LLM 生成质量

**ReAct 推理框架：**
- 最多 25 步工具调用
- 自主决策分析路径
- 结合思考和行动

### 2. 数据采集（internal/fetcher/）
- 支持多种数据源适配
- 定时任务自动采集
- 数据清洗和标准化

### 3. 事件去重（internal/analysis/）
- MD5 哈希快速去重
- 向量相似度语义去重
- 双重保障避免重复

### 4. 通知推送（internal/notify/）
- 多渠道通知（邮件、钉钉、企微）
- 订阅规则匹配
- 异步消息队列

### 5. 监控运维（internal/metrics/）
- Prometheus 指标采集
- 健康检查机制
- 审计日志追踪

## 总结

### 项目特点

1. **标准的 Go 项目布局**
   - 遵循 Go 社区最佳实践
   - internal 目录保证代码私有性
   - 清晰的分层架构

2. **核心创新：AI Agent 协作**
   - 5 个 Agent 串联处理安全事件
   - Supervisor 智能路由
   - RAG + ReAct 技术栈

3. **完善的基础设施**
   - 缓存、锁、重试、并发控制
   - 监控、健康检查、审计日志
   - 完整的运维支持

4. **良好的扩展性**
   - 插件系统
   - 事件驱动架构
   - 多数据源适配

### 开发建议

1. **新增功能时**：
   - 先在 internal/model 定义数据模型
   - 在 internal/repository 实现数据访问
   - 在 internal/service 实现业务逻辑
   - 在 internal/controller 暴露 API

2. **新增 Agent 时**：
   - 在 internal/ai/agent 创建新 Agent
   - 在 internal/ai/tools 添加所需工具
   - 在 internal/workflow 编排流程

3. **新增数据源时**：
   - 在 internal/fetcher 实现适配器
   - 在 internal/scheduler 配置定时任务
