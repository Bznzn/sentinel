## 1. 项目简介

### 1.1 项目概述

Sentinel 是一个基于多 Agent 协作架构的企业安全事件智能研判平台。系统结合大语言模型（DeepSeek V3）、向量数据库（Milvus）和 RAG 检索增强生成技术，实现安全事件的自动采集、智能提取、语义去重、AI 风险评估和解决方案生成。

### 1.2 核心功能

• 多源数据采集：支持从漏洞库、威胁情报平台、厂商公告、GitHub、RSS 等多种数据源自动采集安全事件
• 智能事件提取：使用 LLM 从非结构化数据中自动提取关键信息
• 语义去重过滤：基于 MD5 哈希和向量相似度的智能去重
• AI 风险评估：自动评估安全事件的风险等级（0-100 分）
• 智能方案生成：基于 ReAct 推理循环，结合历史事件和知识库生成处置方案
• 实时流式展示：通过 SSE 实时展示 Agent 协作过程和推理链路
• 交互式 AI 助手：支持自然语言对话查询事件、分析威胁、生成报告

### 1.3 技术亮点

• 5 个 Agent 串联的处理管道：数据采集 → 智能提取 → 去重过滤 → 风险评估 → 方案生成
• Supervisor 多 Agent 路由：智能分发用户请求到专业 Agent
• RAG 技术应用：Milvus 向量数据库 + 豆包 Embedding（1024 维）
• ReAct 推理框架：最多 25 步工具调用，自主决策分析路径
• SSE 流式通信：实时展示 AI 思考过程，提升用户体验

### 2.2 技术栈

• 语言：Go 1.24
• Web 框架：GoFrame v2

• 向量数据库：Milvus v2.5.10
• 关系数据库：MySQL 8.0

前端技术栈：
• 框架：React 18 + TypeScript 5.6
• 构建工具：Vite 6.0
• 样式：Tailwind CSS 3.4
• 状态管理：Zustand 4.5
• 图表：ECharts 5.4
• 动画：Framer Motion 11.0
• Markdown 渲染：react-markdown 9.0
• 路由：React Router 6.22
• 请求：Axios + React Query

## 4. 快速启动

### 4.1 克隆项目

```bash
git clone https://github.com/your-repo/Sentinel.git
cd Sentinel
```

### 4.2 启动 Milvus 向量数据库

第一步：进入 Docker 配置目录
```bash
cd manifest/docker
```

第二步：启动 Milvus 集群
```bash
docker-compose up -d
```

第三步：等待服务启动（约 90 秒）
```bash
# 查看容器状态
docker-compose ps

# 应该看到以下容器都在运行：
# - etcd
# - minio
# - milvus-standalone
# - attu
```

第四步：访问 Attu 管理界面（可选）
• 地址：http://localhost:8000
• 用途：可视化管理 Milvus 向量数据库

### 4.3 启动 MySQL 数据库

返回项目根目录：
```bash
cd ../..
```

启动 MySQL：
```bash
docker-compose up -d mysql
```

验证 MySQL 启动：
```bash
# 查看容器状态
docker ps | grep mysql

# 测试连接（密码：sentinel123）
mysql -h 127.0.0.1 -P 3307 -u root -p
```

### 4.4 配置后端

第一步：复制配置文件
```bash
cp manifest/config/config.yaml manifest/config/config.local.yaml
```

第二步：编辑配置文件
打开 `manifest/config/config.local.yaml`，修改以下关键配置：

```yaml
# DeepSeek V3 模型配置
ds_think_chat_model:
  api_key: "your-ark-api-key-here"  # 替换为你的 Ark API Key
  base_url: "https://ark.cn-beijing.volces.com/api/v3"
  model: "deepseek-v3-1-terminus"

# 豆包 Embedding 模型配置
doubao_embedding_model:
  api_key: "your-ark-api-key-here"  # 替换为你的 Ark API Key
  model: "ep-20260222183953-gv8q5"

# MySQL 数据库配置
database:
  host: "127.0.0.1"
  port: "3307"
  user: "root"
  pass: "sentinel123"
  name: "fo_sentinel"

# 知识库文档目录（绝对路径）
file_dir: "D:/your/path/to/knowledge_docs"  # 替换为实际路径
```

第三步：安装 Go 依赖
```bash
go mod download
```

### 4.5 启动后端服务

```bash
go run main.go
```

启动成功后，你应该看到类似输出：
```
2024-01-15 10:30:00.000 [INFO] Server started at :6872
2024-01-15 10:30:00.001 [INFO] Milvus connected successfully
2024-01-15 10:30:00.002 [INFO] MySQL connected successfully
```

后端服务地址：http://localhost:6872

打开新的终端窗口：

第一步：进入前端目录

```bash
cd web
```

## 5. 功能模块详解

### 5.1 Dashboard（仪表盘）

功能概述：
• 安全态势总览，展示关键指标和趋势
• 实时更新事件统计数据
• 可视化图表展示

主要组件：
1. 统计卡片
   - 事件总数
   - 今日新增事件
   - 严重事件数量
   - 处理中事件数量

2. 事件趋势图
   - 最近7天的事件数量趋势
   - 按严重程度分类展示
   - 支持时间范围切换

3. 严重程度分布饼图
   - Critical（严重）
   - High（高危）
   - Medium（中危）
   - Low（低危）
   - Info（信息）

4. 安全漏斗
   - 展示事件处理流程
   - 从新增到已处理的转化率

使用方法：
• 访问 http://localhost:3001/dashboard
• 页面会自动加载最新数据
• 点击图表可查看详细信息

### 5.2 事件管理（Events）

功能概述：
• 查看和管理所有安全事件
• 支持搜索、过滤、排序
• 批量操作事件状态

主要功能：
1. 事件列表
   - 显示事件标题、严重程度、状态、时间
   - 支持分页（默认20条/页）
   - 点击事件可查看详情

2. 搜索和过滤
   - 关键词搜索：搜索标题和描述
   - 严重程度过滤：critical/high/medium/low/info
   - 状态过滤：new/processing/resolved/ignored
   - 时间范围过滤

3. 批量操作
   - 批量更新状态
   - 批量标星
   - 批量删除

4. 事件详情
   - 完整的事件信息
   - CVE编号和CVSS评分
   - 受影响厂商和产品
   - AI风险评估结果
   - 处置建议

使用方法：
```
1. 访问 http://localhost:3001/events
2. 使用搜索框输入关键词
3. 使用过滤器筛选事件
4. 点击事件行查看详情
5. 勾选多个事件进行批量操作
```

### 5.3 事件分析（Event Analysis）

功能概述：
• 多 Agent 协作分析安全事件
• 实时展示 5 个 Agent 的处理过程
• 可视化推理链路和思考过程

5 个 Agent 处理流程：

1. 数据采集 Agent
   - 从数据库扫描 status='new' 的事件
   - 最多处理 10 条事件
   - 显示采集到的事件数量

2. 智能提取 Agent
   - 使用 DeepSeek V3 提取结构化信息
   - 提取：标题、CVE、严重程度、厂商、产品
   - 显示提取成功的事件数量

3. 去重过滤 Agent
   - 基于 MD5 哈希去重
   - 过滤重复和相似事件
   - 显示去重后的事件数量

4. 风险评估 Agent
   - AI 评分（0-100 分）
   - 评估严重程度和影响范围
   - 生成风险因素和建议

5. 解决方案 Agent
   - ReAct 推理循环（最多 25 步）
   - 调用 6 个工具获取信息
   - 生成完整的处置方案

使用方法：
```
1. 访问 http://localhost:3001/events/analysis
2. 点击"开始分析"按钮
3. 观察 5 个 Agent 的实时处理过程
4. 查看每个 Agent 的输出结果
5. 查看最终生成的处置方案
```

可视化功能：
• Agent 流程图：展示 5 个 Agent 的执行顺序
• 实时日志：显示每个 Agent 的思考过程
• 风险评分仪表盘：可视化风险评分
• 推理链路图：展示 ReAct 推理过程

### 5.4 AI 助手（Chat）

功能概述：
• 基于 Supervisor 多 Agent 路由的智能对话系统
• 支持自然语言查询安全事件、分析威胁、生成报告
• 实时流式展示 AI 思考过程和工具调用
• 支持上下文记忆和多轮对话

Supervisor 路由机制：
系统会根据用户问题自动路由到最合适的专业 Agent：

1. 事件查询 Agent
   - 处理事件检索、统计、筛选类问题
   - 示例："最近有哪些严重漏洞？"
   - 工具：数据库查询、事件统计

2. 威胁分析 Agent
   - 处理威胁情报分析、风险评估类问题
   - 示例："分析 CVE-2024-1234 的影响范围"
   - 工具：RAG 检索、风险评估

3. 报告生成 Agent
   - 处理报告生成、总结归纳类问题
   - 示例："生成本周安全事件周报"
   - 工具：数据聚合、Markdown 生成

4. 通用对话 Agent
   - 处理一般性问题和闲聊
   - 示例："你好"、"帮我解释一下 XSS 漏洞"

使用方法：
```
1. 访问 http://localhost:3001/chat
2. 在输入框输入问题
3. 观察 Supervisor 路由决策
4. 查看专业 Agent 的实时处理过程
5. 阅读 AI 生成的回答
```

高级功能：
• 工具调用可视化：实时展示 Agent 调用的工具和参数
• 推理链路展示：显示 ReAct 推理的每一步思考
• 上下文管理：支持多轮对话，记忆历史信息
• 流式输出：SSE 实时展示生成过程，提升体验

示例对话：
```
用户：最近7天有多少个严重漏洞？
AI：[路由到事件查询Agent] → [调用数据库查询工具] →
    "根据查询结果，最近7天共发现 15 个严重漏洞..."

用户：分析其中最严重的一个
AI：[路由到威胁分析Agent] → [调用RAG检索] → [调用风险评估] →
    "CVE-2024-XXXX 是一个远程代码执行漏洞..."

用户：生成一份分析报告
AI：[路由到报告生成Agent] → [数据聚合] → [Markdown生成] →
    "# 安全事件分析报告\n\n## 概述\n..."
```

### 5.5 订阅管理（Subscriptions）

功能概述：
• 订阅关注的安全事件关键词
• 自动匹配新事件并推送通知
• 支持多种通知渠道（邮件、钉钉、企业微信）
• 灵活的订阅规则配置

主要功能：
1. 创建订阅
   - 设置订阅名称和描述
   - 配置关键词（支持多个）
   - 选择严重程度过滤
   - 设置通知渠道

2. 订阅列表
   - 显示所有订阅规则
   - 查看匹配事件数量
   - 启用/禁用订阅
   - 编辑和删除订阅

3. 匹配规则
   - 标题匹配：事件标题包含关键词
   - 描述匹配：事件描述包含关键词
   - 厂商匹配：受影响厂商包含关键词
   - 产品匹配：受影响产品包含关键词
   - 严重程度：只匹配指定级别的事件

4. 通知渠道
   - 邮件通知：发送到指定邮箱
   - 钉钉机器人：发送到钉钉群
   - 企业微信：发送到企业微信群
   - Webhook：自定义 HTTP 回调

使用方法：
```
1. 访问 http://localhost:3001/subscriptions
2. 点击"新建订阅"按钮
3. 填写订阅信息：
   - 名称：例如"Apache 漏洞监控"
   - 关键词：例如"Apache,Tomcat,Struts"
   - 严重程度：选择 critical,high
   - 通知渠道：配置邮箱或 Webhook
4. 保存订阅
5. 系统会自动匹配新事件并发送通知
```

订阅示例：
```yaml
订阅名称: 关键基础设施漏洞
关键词: Windows,Linux,VMware,Cisco
严重程度: critical,high
通知渠道:
  - 邮件: security-team@company.com
  - 钉钉: https://oapi.dingtalk.com/robot/send?access_token=xxx
匹配逻辑: 标题或描述包含任一关键词，且严重程度为严重或高危
```

认证方式：暂无（后续可添加 JWT Token）

### 6.2 事件管理接口

#### 6.2.1 获取事件列表

```
GET /api/event/list
```

请求参数：
```json
{
  "page": 1,
  "pageSize": 20,
  "keyword": "Apache",
  "severity": "critical,high",
  "status": "new,processing",
  "startTime": "2024-01-01",
  "endTime": "2024-01-31"
}
```

响应示例：
```json
{
  "code": 0,
  "message": "success",
  "data": {
    "total": 127,
    "list": [
      {
        "id": 1,
        "title": "Apache Struts 远程代码执行漏洞",
        "cve": "CVE-2024-1234",
        "severity": "critical",
        "status": "new",
        "riskScore": 95,
        "createdAt": "2024-01-15T10:30:00Z"
      }
    ]
  }
}
```

#### 6.2.2 获取事件详情

```
GET /api/event/detail/:id
```

响应示例：
```json
{
  "code": 0,
  "message": "success",
```

### 6.3 Pipeline 接口

#### 6.3.1 启动事件分析流水线（SSE）

```
GET /api/event/pipeline/stream
```

响应格式：Server-Sent Events (SSE)

事件类型：
```
event: agent_start
data: {"agent": "数据采集Agent", "status": "running"}

event: agent_output
data: {"agent": "数据采集Agent", "output": "扫描到 10 条新事件"}

event: agent_complete
data: {"agent": "数据采集Agent", "status": "completed"}

event: pipeline_complete
data: {"status": "success", "processedCount": 8}
```

使用示例（JavaScript）：
```javascript
const eventSource = new EventSource('http://localhost:6872/api/event/pipeline/stream');

eventSource.addEventListener('agent_output', (e) => {
  const data = JSON.parse(e.data);
  console.log(`${data.agent}: ${data.output}`);
});

eventSource.addEventListener('pipeline_complete', (e) => {
  console.log('Pipeline completed');
  eventSource.close();
});
```

## 8. 常见问题

### 8.1 启动问题

问题 1：Milvus 启动失败
```
错误信息：Error: failed to connect to milvus
```

解决方案：
```bash
# 1. 检查 Docker 容器状态
cd manifest/docker
docker-compose ps

# 2. 查看 Milvus 日志
docker-compose logs milvus-standalone

# 3. 重启 Milvus
docker-compose restart milvus-standalone

# 4. 等待 90 秒后重试
```

问题 2：MySQL 连接失败
```
错误信息：Error 1045: Access denied for user 'root'@'localhost'
```

解决方案：
```bash
# 1. 检查 MySQL 容器状态
docker ps | grep mysql

# 2. 验证密码是否正确（默认：sentinel123）
mysql -h 127.0.0.1 -P 3307 -u root -p

# 3. 检查配置文件中的数据库配置
cat manifest/config/config.local.yaml | grep -A 5 database
```

问题 3：前端无法连接后端
```
错误信息：Network Error / ECONNREFUSED
```

解决方案：
```bash
# 1. 确认后端服务已启动
curl http://localhost:6872/api/health

# 2. 检查后端日志
tail -f resource/log/server.log

# 3. 确认端口未被占用
netstat -ano | findstr 6872  # Windows
lsof -i :6872                # Linux/Mac
```

### 8.2 运行时问题

问题 4：API 调用超时
```
错误信息：Request timeout / Context deadline exceeded
```

解决方案：
```yaml
# 增加超时时间（config.yaml）
ds_think_chat_model:
  timeout: 120  # 秒
  max_retries: 3
```

问题 5：向量检索结果不准确

解决方案：
```bash
# 1. 重建向量索引
curl -X POST http://localhost:6872/api/milvus/rebuild-index

# 2. 调整相似度阈值
# 在配置文件中修改
milvus:
  similarity_threshold: 0.7  # 降低阈值以获得更多结果
```

问题 6：SSE 连接断开

解决方案：
```javascript
// 前端添加自动重连逻辑
const connectSSE = () => {
  const eventSource = new EventSource(url);

  eventSource.onerror = () => {
    eventSource.close();
    setTimeout(connectSSE, 3000);  // 3秒后重连
  };
};
```

### 8.3 性能问题

问题 7：事件列表加载慢

优化方案：
```sql
-- 添加数据库索引
CREATE INDEX idx_severity ON events(severity);
CREATE INDEX idx_status ON events(status);
CREATE INDEX idx_created_at ON events(created_at);
```

问题 8：Pipeline 处理速度慢

优化方案：
```yaml
# 调整并发数（config.yaml）
pipeline:
  max_concurrent: 5  # 同时处理的事件数
  batch_size: 10     # 每批处理的事件数
```

知识库文档编写建议：
• 使用清晰的标题和结构
• 包含关键词和术语定义
• 添加实际案例和示例
• 定期更新和维护
• 控制单个文件大小（建议 < 5MB）

### 9.2 事件处理流程

推荐的事件处理工作流：

1. 自动采集阶段
   - 配置数据源和采集频率
   - 设置关键词订阅
   - 启用自动通知

2. 智能分析阶段
   - 运行 Pipeline 进行批量分析
   - 查看 AI 风险评估结果
   - 筛选高危和严重事件

3. 人工研判阶段
   - 查看事件详情和处置建议
   - 结合实际环境评估影响
   - 更新事件状态为"处理中"

4. 处置执行阶段
   - 按照建议方案执行处置
   - 记录处置过程和结果
   - 更新事件状态为"已解决"

5. 总结归档阶段
   - 生成处置报告
   - 更新知识库
   - 分享经验教训

### 9.6 安全建议

1. API 认证
   - 生产环境必须启用 JWT 认证
   - 定期轮换 API Key
   - 使用 HTTPS 加密传输

2. 数据备份
   - 每日备份 MySQL 数据库
   - 每周备份 Milvus 向量数据
   - 备份知识库文档

3. 访问控制
   - 限制 Milvus 和 MySQL 的网络访问
   - 使用防火墙规则
   - 启用审计日志

4. 敏感信息保护
   - 不要在配置文件中硬编码密钥
   - 使用环境变量或密钥管理服务
   - 定期检查日志中的敏感信息泄露
